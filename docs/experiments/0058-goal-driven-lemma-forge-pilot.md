# Experiment 0058: goal-driven lemma-forge preflight

## Question

Can a bounded parallel stream of route-independent intermediary conjectures
generate useful structure without displacing the active E3 proof or creating a
second roadmap?

## Method

The principal-orchestrator profile now defines a goal-driven lemma forge with
at most three active candidates.  Each candidate must have an exact model
tier, a Lean-shaped statement, a named downstream consumer, an equality-case
check, a cheap falsifier, separate truth and leverage assessments, and an
expiry or kill rule.  Promotion requires both a compiling theorem and a
consumer audit.

The first read-only preflight considered local four-point obstructions,
insertion signatures, and equality-case binary fingerprints.

## Result

- The proposed four-point localization theorem was rejected as a duplicate:
  `inConvexPosition_iff_four_subsets` already compiles in `Convexity.lean`.
- A normalized insertion-signature collision family was parked.  Existing
  pair-rank, turn-language, and incoming-star collisions show that equality of
  a compressed local state cannot be assumed to be transition-congruent; the
  proposed replacement currently lacks a new consumer beyond compiled coupled
  failure machinery.
- A binary fingerprint was restricted to the classical Pascal-row lower
  construction and parked as calibration infrastructure.  Requiring such a
  fingerprint for every extremal avoider would risk restating the missing
  upper bound rather than proving an intermediary lemma.
- One conditional survivor remains: a planar rooted-triangle circuit
  elimination lemma.  It would eliminate an intermediate point from two
  nested convex-hull certificates and could normalize deletion-obstruction
  chains independently of decomposability or pivot charging.

These are proposal-level conclusions.  No new circuit-elimination theorem was
implemented or claimed.

## Disposition

The pilot passed the process test by detecting one existing theorem, parking
two true-or-plausible but strategically inert families, and leaving only one
candidate for sharper review.  Before implementation, the rooted-circuit
candidate must receive an exact signed support statement and a concrete
minimal-counterexample consumer.  If either is missing, it expires rather than
entering the Lean backlog.
