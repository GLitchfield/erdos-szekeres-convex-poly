# Ticket 0068: run the post-Batch011 whole-project factory refresh

## Question

After the first rolling wave and its route review produce no executable
Batch011 successor, can a fresh maximum-effort Sol pass generate up to five
semantically new, source-grounded mechanism families without duplicating or
premise-repairing the newly admitted failure memory?

## Decision criteria

The packet must be rebuilt from the fully reconciled post-Ticket-0067 state;
reusing the post-Ticket-0066 context is stale. It must include the exact
`NO-BATCH011-ROUTE-READY` adjudication, current map and portfolio, complete
living idea ledger, all prior factory batches, current Lean declaration index,
literature/source records, the first-wave terminal evidence, and the Batch011
source/rebase/gate audits.

Sol privately generates a broad pool and exposes exactly five ideas only if
five survive. Otherwise it returns `FACTORY-NOVELTY-STOP`. Primary-source
research and unfamiliar or remote machinery are encouraged, including
higher-dimensional lifts, lattice/rotation models, oriented matroids, convex
geometries, projective/algebraic identities, representation theory,
modular-form analogies, topology, probability, optimization, proof complexity,
and defect inversion. These are permissions, not assumptions baked into the
output language.

Each exposed idea must state its precise model tier, sourced versus conjectural
content, semantic novelty delta, consumer ladder, scope ceiling, one bounded
immutable gate, four outcome branches, proof-distance account, anti-leakage
audit, and generation-memory record. No idea is admitted, selected, ranked,
scheduled, assigned, or executed by this ticket.

## Resolution

Run one bounded post-Batch011 maximum-effort Sol factory refresh from a newly
built whole-project context. The first dispatched packet is preserved as an
operational control: an independent packet audit found stale preflight-only
wording in its nominally final question and found that this ticket lacked the
mandatory `Resolution` and `Evidence` headings. Under the frozen mismatch
contract, no proposal from that attempt may be admitted. Root must rebuild the
context after this correction, freeze a new question and standard-schema task
under a disjoint v2 path, authenticate every input, and dispatch the corrected
packet without reusing any unadmitted idea text from the stopped attempt.

This is proposal generation only. A successful provider terminal neither
changes the portfolio nor opens a mathematical execution lane. Root must first
validate the output, independently ground its source and novelty claims, and
use bounded route review before admitting or scheduling a survivor.
