# Ticket 0052: plan exhaustive Fin11 cube coverage

## Question

Can the selected-cube theorem from Ticket 0051 be converted into a bounded,
kernel-checkable theorem covering all 64 assignments of its six cube literals,
without duplicating semantic infrastructure unnecessarily or consuming the
full certificate budget before a downstream Fin11 consumer is fixed?

## Authorization

The user explicitly authorized using all available parallel agent capacity to
plan this work on 2026-08-20. The platform exposes four active slots including
the root orchestrator, so this planning block uses three specialist workers and
the root concurrently, then reuses the slots in later waves. This is not a
claim that the four activities are independent proof routes.

All planning workers are read-only outside disjoint packet-owned report paths.
No Lean/Lake build, certificate regeneration, network call, installation,
destructive action, commit, or push is part of the planning audits.

## Planning gates

1. **Exact symmetry audit.** Determine the actual action of order reversal,
   admissible relabelings, and color duality on the six frozen literals, the
   semantic premise, and the synchronized-five-fan conclusion. Boolean-cube
   symmetry by itself is not admissible.
2. **Semantic-union audit.** Compare the causal cores of all 64 leaves against
   the eight reconstructed semantic families. Identify the reusable union,
   leaf-specific units, and every genuinely missing semantic schema.
3. **Kernel-scaling audit.** Reconstruct exact size distributions and design a
   parameterized checkpoint/module layout with bounded representative pilots.
   Do not run the generator or Lean during this planning gate.
4. **Root architecture.** Freeze an indexed cube-assignment API, an exhaustive
   wrapper theorem, serial-builder protocol, integration order, and downstream
   restriction/relabeling boundary.

Using all three worker slots in one mechanism family exceeds the default
portfolio concentration. The mathematical justification is narrow: symmetry,
semantic coverage, and kernel scaling are conjunctive admission gates for one
already-selected finite theorem; parallel execution reduces planning latency
but does not diversify failure risk or reset the `FP-01` evidence streak.

## Decision criteria

- `FIN11-ALL-CUBE-PLAN-READY`: exact contracts, source partition, resource
  ceilings, representative pilots, aggregate theorem, and downstream consumer
  boundary are all frozen well enough to request execution approval.
- `FIN11-SYMMETRY-REDUCTION`: an exact proved-or-proof-ready action reduces the
  number of certificate leaves without changing the geometric conclusion.
- `FIN11-SEMANTIC-UNION-GAP`: one or more leaf-core clauses lack a project-level
  semantic producer; stop mass generation and isolate those schemas.
- `FIN11-KERNEL-SCALING-GAP`: the projected module/output/build cost exceeds the
  declared ceiling or cannot be bounded from the frozen artifacts.
- `FIN11-NO-GENERALIZATION-CONSUMER`: exhaustive Fin11 coverage can compile but
  no exact restriction/relabeling or compatible-window consumer is credible;
  retain the finite theorem but do not describe it as a load-bearing advance.

## Proof distance

The planning audits themselves have neutral net proof movement and produce

## Resolution

`FIN11-ALL-CUBE-PLAN-READY`.

The planning block closes with neutral proof movement and a revised executable
architecture.  The primary is not 63 additional depth-six leaves.  It uses the
two authenticated alternate-depth-two representatives with units `[-15,111]`
and `[15,111]`; an exact project-level color-duality theorem supplies their
two complements.  Their shared source contains 16,702 semantic clauses in

peak imported learned clauses and 145,159/141,110 peak carry-input bytes.  Both
fit the frozen pre-render limits of 2,048 clauses and 160 KiB.

The execution slate has six unconditional proof-producing threads, two
conditional proof-producing fallback architectures, and one independent
information-gathering audit thread.  Three specialist slots plus the root are
